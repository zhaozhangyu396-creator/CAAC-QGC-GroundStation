# Pixhawk 6C 训练围栏策略

本目录保存两套官方多旋翼稳定版的源码补丁。稳定版信息核验日期：2026-10-16。

| 飞控固件 | 官方版本 | Pixhawk 6C 构建目标 | 自定义能力参数 |
| --- | --- | --- | --- |
| PX4 | v1.17.0 | `px4_fmu-v6c_default` | `GF_NOLAND=1`，配合 `GF_ACTION=2` |
| ArduCopter | Copter-4.7.2 | `Pixhawk6C` | `FENCE_NOLD=1`，配合 `FENCE_ACTION=4` |

具体上游提交、原文件和补丁的 SHA-256、验证结果见各目录的 `manifest.json`。
这些是源码补丁，不是可直接刷写的固件文件；官方原版固件不包含这些修改。

## 行为

围栏触发后尝试制动或悬停。无法进入该模式时保留可运行的原飞行模式，发出报警，由操控员接管。
该策略禁止这一围栏故障原因回退至自动降落；电池、遥控失联、定位等独立故障仍执行其原有策略。
它不检测飞机是否在物理上成功减速，也不承诺制动失效后仍能阻止越界。

两套自定义参数默认均为 `0`，保持原固件行为。地面站通过独有参数及其类型、值识别适配能力，
原生固件仍可读取围栏，不能启用本训练围栏策略。

## 地面站写入顺序

1. 确认无人机连接完成、落地并锁定；读取现有围栏和相关参数。
2. 现有围栏不同时提示替换，并在本地备份原围栏及参数。
3. 设置不降落能力和制动动作，逐项等待飞控参数回报确认。
4. 上传训练走廊外侧的包络多边形，再回读核对每个顶点。
5. 确认最终启用参数后才显示围栏已应用。

中途失败、切换无人机或解锁后停止后续步骤，不会把未确认的状态显示为已应用。
已发出的传输仍可能完成，需要回读确认。围栏写入与航线任务分开，不替换航线。

## 构建与验证范围

补丁应只应用于各自清单中固定的上游提交，并先执行 `git apply --check`。
PX4 构建命令为 `make px4_fmu-v6c_default`；ArduCopter 为
`./waf configure --board Pixhawk6C` 后执行 `./waf copter`。

源码补丁的应用校验和宿主算法测试不等于完整飞控构建、SITL、硬件测试或实际飞行验证。
各项实际完成情况在清单中分别列出；本次没有刷写任何无人机。
